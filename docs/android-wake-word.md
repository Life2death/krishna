# Android hands-free wake word

Android hands-free mode uses a local OpenWakeWord detector to gate speech recognition. It continuously evaluates microphone audio only for **Hey Krishna**. Android speech recognition starts only after the wake word is detected, so idle listening does not request audio focus from apps such as YouTube Music.

## Detector selection

| Detector | Status | Switch |
|---|---|---|
| OpenWakeWord (TFLite/LiteRT) | Primary production detector | Activated via Settings → Wake Word |
| Sherpa-ONNX | Development-only diagnostic | Behind `USE_SHERP_DEV_SWITCH = true` flag |

## Runtime behavior

1. OpenWakeWord captures 16 kHz mono PCM frames with `AudioRecord` and runs TFLite inference.
2. Scores are smoothed across a 5-frame window with a cooldown gate.
3. On match, the detector stops and Android STT captures one command turn.
4. Krishna performs supported native actions, then returns to idle wake-word detection.
5. Failed or empty commands return to idle detection.

Say the wake word, pause briefly, then speak the command. The command-recognition turn can briefly pause music while you speak, but audio is uninterrupted while Krishna is waiting for the wake word.

## Shadow mode

OpenWakeWord operates in shadow mode until the quality gate is met:
- 100+ positive training clips
- 200+ negative training clips
- 3+ distinct environments
- 48+ hours elapsed
- Local evaluation passes recall and false-wake targets
- User explicitly approves activation

## Audio source

Default: built-in microphone. No audio focus is requested while idle.
Bluetooth headset (SCO/HFP) is opt-in with a clear warning about potential music quality impact.

## Privacy

- Training clips stored in app-private storage only
- No network transmission of audio
- Configurable retention; clips deleted after successful evaluation by default
- Diagnostic metadata never includes raw audio or transcript content

## Model

A synthetic TFLite model is generated by the training workflow in `training/openwakeword/`.
See `docs/openwakeword-android.md` for integration details.
